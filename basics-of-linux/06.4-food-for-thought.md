# 🌭 Food for Thought: Working with files

Although the topics covered in this chapter only scratch the surface, they lay the groundwork for a wide range of tasks related to files.

It is also at this point that things start to diverge. The tools described in this chapter are well known and widely available across different Linux distributions. However, users will eventually develop tools that are better suited to their file management tasks, as well as tools for analysing file contents. 

As discussed in [Chapter 4](04-executables.md), adding new tools to your Linux system is fairly simple. Moreover, new tools are more readily available than ever before.

Therefore, it is sufficient to mention this here before moving on to more generic topics applicable to all Linux operating systems.

## Hidden track: Escape character

Escaping is relevant not only to this chapter, but to Linux in general. However, the 'Batch' subchapter presented a command that used _the escape character_ (`\`) - therefore, let's discuss it here.

::: guidance
If you have come from Chapter [CLI](01.1-cli.md#iii-command-line) or Chapter [Arguments](04.1-arguments.md#programs-compiled-into-binaries), welcome! Please read all about the escape character, and then return to the chapter you came from. You are a thorough reader! ✨
:::

Consider the command `find ~ -name "basics-of-linux.png" -exec catimg {} \;` which we used in the [Finding files](06.3-batch.md#finding-files) section.

The `\;` part _escapes_ the semicolon, instructing Bash to _ignore_ it and pass it to the `find` command as it is. Without the escape character, _Bash_ would interpret the semicolon as a command terminator.

Similarly, one can 'escape' a letter 'n' so that it is not just a regular 'n'. Typing `\n` would instruct for example the `echo` command to print the following characters on a new line.

You can try this out by typing the following command: `echo -e "Hello\nNew line"` or `printf "Hei\nMaailma\n"`.

::: terminal
{{USERNAME}}@{{HOSTNAME}}:~$ echo -e "Hello\nNew line"
Hello
New line
{{USERNAME}}@{{HOSTNAME}}:~$ printf "Hei\nMaailma\n"
Hei
Maailma
{{USERNAME}}@{{HOSTNAME}}:~$ █
:::

::: note
You must explicitly enable escaping in `echo` using the `-e` argument and surround the text with quotation marks. The `printf` command also omits the new line by default, so you have to add it if needed.
:::

Escaping any letter or number does not automatically produce a result; the functionality of escaped sequences depends on the context. The `$PS1` example in the 'CLI' chapter used its own set of escape sequences to display certain information. Providing those sequences to `echo`, for example, will not produce the same results.

Below are a couple of widely supported escape sequences.

| Escape sequence | Description |
|-----------------|-------------|
| `\n` | Newline. Moves to next line. |
| `\t` | Tab. Fixed width whitespace. |
| `\r` | Carriage return. Moves cursor to line start. |
| `\\` | Backslash. Escape the escape - literal backslash. |
| `\0` | Null character aka NUL byte. |

::: question
What will be printed when the command `echo -e "Hello\rB"` is run? Check the echo manual page (`man echo`) to find out even more information.
:::
