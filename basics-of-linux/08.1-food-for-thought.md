# 🌭 Food for Thought: Redirections

The table below shows all the redirection options:

| Syntax              | Description                                           |
|---------------------|-------------------------------------------------------|
| `cmd > file`        | cmd's `stdout` to `file` (overwrite)                  |
| `cmd >> file`       | cmd's `stdout` to `file` (append)                     |
| `cmd 2> file`       | cmd's `stderr` to `file` (overwrite)                  |
| `cmd 2>> file`      | cmd's `stderr` to `file` (append)                     |
| `cmd 2>&1`          | cmd's `stderr` to wherever `stdout` currently points  |
| `cmd < file`        | cmd's `stdin` from `file`                             |
| `cmd1 \| cmd2`      | Pipe: `stdout` of `cmd1` becomes `stdin` of `cmd2`    |
| `cmd1 2>&1 \| cmd2` | Pipe both `stdout` and `stderr` of `cmd1` to `cmd2`   |

Some useful shortcuts that are dependent on bash are listed in another table below:

| POSIX                     | Bash shorthand    |
|---------------------------|-------------------|
| `cmd > file 2>&1`         | `&> file`         |
| `cmd >> file 2>&1`        | `&>> file`        |
| `cmd1 2>&1 \| cmd2`       | `cmd1 \|& cmd2`   |

## Input redirection vs piping

At first glance, it might seem that there is no difference between input redirection and piping functionality. To be fair, the end result does indeed look identical.

However, piping connects processes with the (temporary) output of the first process acting as the input for the second. Where, by contrast, input redirection involves only one process, with input read from a (permanent) file rather than temporary process output.

Input redirection always involves disk input/output (reading from a file), whereas piping does not necessarily do so.

## /dev/null

To discard the output of a command, you can safely redirect it to the `/dev/null` special character device file. This device accepts all write requests, and its sole purpose is to discard any data written to it.

The command: `cmd1 > /dev/null 2>&1` discards all messages written to both `stdout` and `stderr`, meaning nothing is preserved.

This feature is useful for e.g. background processes or scripts whose output is not important.
