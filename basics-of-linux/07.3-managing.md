# Managing processes

OK, now you know how to find and launch running processes yourself. Next, let's find out how to get rid of them.

::: guidance
Processes usually behave well and exit once they have finished their job. However, sometimes it is necessary to terminate an unwanted or 'hanging' process.
:::

This is done by sending signals to the processes.

## Signals

A signal is a short message that a user asks the kernel to deliver to a process, typically instructing it to pause, resume or terminate. We've already used two of these signals: `SIGINT` and `SIGTSTP`.

Each signal has both a name, such as SIGINT, and a number. You can list all the signals recognised by your system with the command `kill -l`.

::: terminal
{{USERNAME}}@{{HOSTNAME}}:~$ kill -l
 1) SIGHUP	 2) SIGINT	 3) SIGQUIT	 4) SIGILL	 5) SIGTRAP
 6) SIGABRT	 7) SIGBUS	 8) SIGFPE	 9) SIGKILL	10) SIGUSR1
11) SIGSEGV	12) SIGUSR2	13) SIGPIPE	14) SIGALRM	15) SIGTERM
...
{{USERNAME}}@{{HOSTNAME}}:~$ █
:::

### kill

Despite its name, the `kill` command can be used to send any supported signal to a process. By default it sends `SIGTERM` (number `15`), which asks a process to terminate gracefully, giving it a chance to clean up before exiting.

Start a long-running process in the background, note its PID, and then terminate it with `kill`.

::: terminal
{{USERNAME}}@{{HOSTNAME}}:~$ sleep 1000 &
[1] 140
{{USERNAME}}@{{HOSTNAME}}:~$ kill 140
[1]+  Terminated              sleep 1000
{{USERNAME}}@{{HOSTNAME}}:~$ █
:::

Instead of the PID, you can also refer to a background job by its job ID with a `%` prefix, as listed by the `jobs` command:

::: terminal
{{USERNAME}}@{{HOSTNAME}}:~$ sleep 1000 &
[1] 141
{{USERNAME}}@{{HOSTNAME}}:~$ jobs
[1]+  Running                 sleep 1000 &
{{USERNAME}}@{{HOSTNAME}}:~$ kill %1
[1]+  Terminated              sleep 1000
{{USERNAME}}@{{HOSTNAME}}:~$ █
:::

So, the default setting (SIGTERM, 15) instructs the process to end execution on its own terms. This allows the process to write and close any open files, as well as manage any resource reservations.

However, sometimes a process does not respond to this polite request and must be terminated by the kernel (e.g. if it is hanging).

We can ask the kernel to do this with specifying the signal that we want to send: `kill -9 141`, or by using the signal's name, e.g. `kill -SIGKILL 141`.

::: beware
The process cannot ignore `SIGKILL` (number `9`), which means it cannot save its work or clean up temporary files. `SIGKILL` should only ever be used as a last resort.
:::

### kill 'em all

In some cases, you may not know the PID. Alternatively, your command may run multiple (sub)processes, each with a different PID. Killing wrong processes in a process group can result in a game of whack-a-mole when trying to terminate the master process, since the command's implementation spawns new ones.

Let's launch some processes – for example, enter the command `sleep 1000 &` three times.

Type `ps` with no arguments to see the processes currently running. Verify the running sleep commands and observe their PIDs.

::: terminal
{{USERNAME}}@{{HOSTNAME}}:~$ sleep 1000 &
[1] 142
{{USERNAME}}@{{HOSTNAME}}:~$ sleep 1000 &
[2] 143
{{USERNAME}}@{{HOSTNAME}}:~$ sleep 1000 &
[3] 144
{{USERNAME}}@{{HOSTNAME}}:~$ ps
    PID TTY          TIME CMD
    140 pts/0    00:00:00 bash
    142 pts/0    00:00:00 sleep
    143 pts/0    00:00:00 sleep
    144 pts/0    00:00:00 sleep
    150 pts/0    00:00:00 ps
{{USERNAME}}@{{HOSTNAME}}:~$ █
:::

Now, you could go and terminate processes by entering the `kill` command and manually entering the PIDs as arguments. However, there is an easier way. Enter the command `pidof sleep` to list the relevant PIDs.

::: terminal
{{USERNAME}}@{{HOSTNAME}}:~$ pidof sleep
144 143 142
{{USERNAME}}@{{HOSTNAME}}:~$ █
:::

Next, use the **command substitution** feature. Enter the following command: `kill $(pidof sleep)`.

::: terminal
{{USERNAME}}@{{HOSTNAME}}:~$ kill $(pidof sleep)
{{USERNAME}}@{{HOSTNAME}}:~$
[1]   Terminated              sleep 1000
[2]-  Terminated              sleep 1000
[3]+  Terminated              sleep 1000
{{USERNAME}}@{{HOSTNAME}}:~$ █
:::

Pressing `Enter ↵` will empty the text buffer and print out a list of terminated background processes.

::: tip
Command substitution is a useful feature that can be used with any command. Essentially, the `$(cmd)` part is replaced with the `cmd`'s output.
:::

And, as you might have guessed, there's an even easier way to achieve this result. First, start some sleep processes and verify that they are running with the command `pgrep sleep`. Then use the `pkill sleep` command to terminate them.

::: terminal
{{USERNAME}}@{{HOSTNAME}}:~$ sleep 1000 &
[1] 154
{{USERNAME}}@{{HOSTNAME}}:~$ sleep 1000 &
[2] 155
{{USERNAME}}@{{HOSTNAME}}:~$ sleep 1000 &
[2] 156
{{USERNAME}}@{{HOSTNAME}}:~$ pgrep sleep
154
155
156
{{USERNAME}}@{{HOSTNAME}}:~$ pkill sleep
[1]   Terminated              sleep 1000
[2]-  Terminated              sleep 1000
[3]+  Terminated              sleep 1000
{{USERNAME}}@{{HOSTNAME}}:~$ █
:::

You may need to press Enter to clear the text buffer.

::: note
It's worth checking out the differences between the `pidof` and `pgrep` commands. The latter is likely to be more appropriate for most use cases, but be aware of its default behaviour to avoid terminating too many processes.
:::
